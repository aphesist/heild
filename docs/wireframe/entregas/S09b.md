# Entrega S09b · Armazenamento com qualquer provedor

**Branch:** `wf-s09-arquivos-config` (o `wireframe` trazido antes, até a S08d) · **15/11/2026**

Pedido do Enzo, repassado pela coordenação: "não deve funcionar só o Drive; os outros clouds padrão do mercado devem estar presentes também". Um escritório do piloto usa servidor local próprio.

## O que ficou pronto

| Item do pedido | O que a tela faz | Onde |
| --- | --- | --- |
| 1. Dropbox e Box | Entram em "Conectar nuvem" com a janela de autorização simulada (a mesma do Google e da Microsoft: o que a Heild pede, Permitir, Cancelar, erro do provedor) | `telas/config/armazenamento-s09b.tsx` (`JanelaAutorizacao`, `AutorizarNuvem`) |
| 2. Servidor local (agente Heild) | Windows ou Linux; baixar o agente; código de pareamento (15 min, uso único); aguardar o agente; escolher as pastas compartilhadas; cartão com online/offline, versão, última sincronização, arquivos, quem pareou; editar pastas; revogar o dispositivo; aviso de que o agente só abre conexão de saída e nenhuma porta é aberta | `armazenamento-s09b.tsx` (`ParearAgente`, `CartaoAgente`), `dados/armazenamento.ts` |
| 3. Onde ficam os arquivos | Faixa no topo de Armazenamento e nota em cada passo: os arquivos ficam no armazenamento do escritório; a Heild guarda só o índice e o texto para os integrantes | `FaixaOndeFicam` |
| 4. Google Workspace | Escolha "Workspace" ou "pessoal"; com Workspace, o passo a passo para o administrador (Controles de API, ID do cliente OAuth para copiar, enviar ao administrador); a autorização é recusada até "o administrador já liberou"; selo "Google Workspace" no conector | `AutorizarNuvem`, `passosWorkspace` |
| 5. Serviços e Raio-X para qualquer provedor | `servicos.nuvens` (autorizar, verificar a liberação do Workspace, parear e revogar o agente); `servicos.arvore.ler(raiz, progresso, provedor)`; `servicos.armazenamento.listar/enviar` com `provedor` opcional; Raio-X com "Onde ler" entre as nuvens e o servidor local conectados; C9 com `dropbox`, `box` e `servidor_local` | `servicos/conectores.ts`, `servicos/documentos.ts`, `telas/raio-x/RaioXTela.tsx`, `dados/conectores.ts` |
| 6. Dados pelo núcleo | Conectores de armazenamento e agentes no `registro_tela` (local e Supabase), sem migração e sem tocar no HEILD-PROD (combinado com a coordenação) | `cfg.arm.conectores`, `s09:arm:agentes` |

Também: o Armazenamento passou a ter padrão por escritório e saiu do aviso de dados fixos; o **Horizonte** é o piloto, com o servidor local `SRV-HORIZONTE` como padrão. A manutenção das pastas, o bloco do Raio-X, a implantação (passo 5) e o FAQ do Suporte falam de qualquer provedor. O painel Demonstração ganhou "Agente local ficar offline / voltar online".

## Ficou de fora

- Não há instalador nem agente de verdade: baixar mostra um aviso, e o pareamento é simulado.
- `PADRAO_DE_INTERFACE.md` ainda não estava no `wireframe` quando trabalhei; as telas seguem o kit e o padrão das outras abas de Configurações.

## Como testar

```bash
cd app
npm run typecheck && npm run build
npx vite --port 6100
node scripts/s09b-armazenamento.cjs /tmp/s09b     # 24 verificações
```

Na mão: Configurações › Armazenamento › Conectar nuvem, escolha Dropbox, Box, Google Drive (Workspace) ou Servidor local. No painel Demonstração, troque para o Horizonte para ver o piloto com o servidor local, e use "Agente local ficar offline".
